# Meridian test coverage matrix

This matrix records the release test surface from the repository, not a line-coverage percentage. The baseline had **39** tests. The final suite has **103** tests (**64 new meaningful cases**) and was run with `npm test`.

## Judge Lab control mapping

| Judge Lab control | Implementation boundary | Automated evidence | Expected invariant | Observed result |
|---|---|---|---|---|
| Evidence integrity | `src/accounting.js`, `src/validator.js`, `src/decisions.js` | `agent cannot submit without reading evidence, ledger and policy`; `agent cannot fabricate a source ID or override a source dispute`; `validator rejects a proposal that omits one source document`; `evidence request is a revision-bound draft` | Findings reference current source documents and policy; missing or fabricated evidence cannot pass | PASS |
| Deterministic accounting | `src/money.js`, `src/accounting.js`, `src/validator.js` | `half-up money conversion is exact, symmetric and rejects fractional cents`; `source and ledger produce expected missing, duplicate, rate, credit and disputed cases`; `independent checker rejects a balanced but incorrect proposal`; `validator rejects entries with two-sided or negative amounts`; `validator rejects unsupported accounts and currencies` | Minor-unit arithmetic, currency conversion, balance, and account obligations are rebuilt independently of the agent narrative | PASS |
| Source conflict | `src/source-selection.js`, `src/cases.js` | `conflicting invoices invalidate approvals and require current controller source authority`; `selectedInvoices keeps all candidates until a current controller choice exists`; `controller source choice resolves a conflict and records its digest`; API invalid source choice test | Competing invoices remain visible and blocked until a current controller choice is bound to the candidate digest | PASS |
| Late evidence / freshness | `src/revisions.js`, `src/workflow.js` | `late credit preserves past journals and produces a compensating revision and stale report`; `source update rejects a stale approval with no ledger mutation`; `invalidate marks downstream reports stale while retaining historical approvals`; `prepared report becomes stale when a later communication changes evidence`; `in-flight evidence changes cannot publish a stale investigation result` | A changed source invalidates affected downstream conclusions; historical journals remain intact; fresh review is required | PASS |
| Human approval protection | `src/workflow.js` | `approval posts once, balances ledger, and repeats return the original posting`; `approval rejects missing proposal, wrong revision and non-controller role`; `approval rejects a blocked IC-1047 proposal without posting`; `reject requires a reason and records reviewer feedback`; `email instructions cannot approve, modify policy, or erase a source dispute` | Only a current, independently validated proposal can be approved by the controller role; rejected/blocked/stale work cannot post | PASS |
| Duplicate-safe posting | `src/store.js`, `src/workflow.js`, `src/runner.js` | `OS-killed worker before-commit recovers with exactly one posting`; `OS-killed worker after-commit recovers with exactly one posting`; `two processes race the same approval and only one commits a journal`; `pending review survives database reopen; repeated approval after restart posts once`; `credit retry is idempotent and newer content preserves document history` | Retries and crash boundaries produce at most one correction journal and preserve source history | PASS |
| Failure recovery / checkpoints | `src/runner.js`, `src/workflow.js` | `real process termination retains checkpoints and resume skips completed work`; `resume keeps completed current checkpoints and investigates only unfinished bundles`; `worker startup marks interrupted runs and leaves fingerprints and journals intact`; `recovery marks a running run interrupted and emits an audit event`; `failed agent runs are persisted as failed with no correction journals` | Interruptions are explicit, checkpoints survive restart, completed work is not duplicated, and provider failure fails closed | PASS |

## Honest limits

The suite does not claim source-line coverage, randomized fuzzing, authenticated reviewer identity, a multi-process run-start lock, or production ERP/database behavior. API tests use a disposable local database and do not authenticate against live sponsor systems. Judge Lab's live challenge logic remains unchanged; these tests exercise its existing control boundaries and the underlying workflow.
